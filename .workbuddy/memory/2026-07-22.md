# 2026-07-22 视频生成流水线性能优化 + 口型同步修复

## 任务
诊断并修复数字人 SDK 两大问题：帧率瓶颈（目标≥24fps）与口型同步异常。

## 环境要点（WSL Ubuntu-22.04）
- WSL 发行版名是 `Ubuntu-22.04`（不是 Ubuntu），wsl 调用：`wsl -d Ubuntu-22.04 -- bash -lc "..."`
- **WSL /tmp 会在 VM 空闲重启后被清空**（uptime 证实 VM 会关机）→ 持久文件放项目 build/ 或 Windows temp（/mnt/c/...）
- build.sh 是 CRLF 行尾 → 用 `bash build.sh`，且其 sed 步骤会失败 → 配置后需手动跑：
  `find build -name build.make -exec sed -i -e 's|/usr/lib/x86_64-linux-gnu/libjpeg.so|$HOME/.local/lib/libjpeg.so|g' -e 's|.../libsqlite3.so|$HOME/.local/lib/libsqlite3.so|g' {} +`
- 多层 shell 转义 for 循环会丢变量 → 一律写脚本文件再 `bash -l script.sh`
- ffmpeg/ffprobe 已用 apt 安装（sudo 密码 ccBk4681）
- vcpkg OpenCV 4.12 静态库链接依赖链复杂 → 手工链接测试程序时复用 build/examples/CMakeFiles/*/link.txt 整行替换
- /mnt/c (drvfs) 写 JPEG 帧极慢（~0.5-1s/张）→ 性能测试帧输出到 WSL 原生路径（~/...）

## 机器
AMD Ryzen 7 7840HS（8 物理核 / 16 SMT），16 线程是 SMT 不是物理核 → ncnn 8 线程 + 其余流水线线程互相争抢 SMT 兄妹核是推理负载下变慢 ~2.4× 的主因

## 诊断结论（已验证）
### 口型失效根因（生产路径 src/ vs 参考路径 examples/video_output_test.cpp）
1. AudioProcessor 逐 400 样本帧独立处理 → 单帧 mel 1×80 → 单帧 CMVN（均值=帧本身）→ **输出 100% 全零特征**（已实测 1999/1999 包全零）
2. 单帧 min-max 归一化摧毁帧间能量动态
3. InferenceWorker::MelToNCNN 布局转置错误（w=80,h=T）→ 推理 ret=-100 全部失败（实测）
4. FaceToNCNN 双份完整人脸、无下半脸遮罩 → 模型走捷径复制原嘴
5. 缺 16 帧 mel 时序窗（Wav2Lip 需 80×16）
### 帧率根因
1. mel 驱动匹配 → 100 task/s（4× 放大）+ 每个失败任务重试 3 次
2. perf_benchmark 音频重叠推送（hop=160 推 400 块）→ 环形窗数据重复，时间轴拉长 2.5×
3. FaceToNCNN 逐像素 at<> 循环
4. 全图（1920×1384）渲染：float 融合链 + float 锐化

## 修复（已实施）
- mel_feature_extract: extract() 增加 apply_minmax 参数（默认 true 兼容）
- audio_processor: dB 域 log-mel 直出（禁单帧 min-max/CMVN）、流式 EMA RMS、PTS 修 +1hop 偏移
- pipeline.cpp MatcherThread: 重写为 face 驱动 + 80×16 滑窗装配 + 滚动上下文 min-max/CMVN
- inference_worker: MelToNCNN 布局修正（w=T,h=80）、FaceToNCNN 下半脸遮罩+向量化+指针缓存
- output_processor: 新增 ProcessROI（ROI 内 warp/融合/锐化/贴回）、doSharpen 改 uint8 域、doFaceFusion 改 blendLinear
- pipeline: 新增 enable_frame_pacing / mel_window_frames / mel_context_frames / opencv_num_threads 配置、SetInferenceThreads API
- render_thread: 改用 ProcessROI
- 新增 examples/pipeline_lipsync_test.cpp（帧率+口型相关+MP4 验收）

## 扫参后追加修复
- doFaceFusion 改 blendLinear（注意：**blendLinear 权重必须 CV_32FC1 单通道**，传 3 通道会触发 -215 断言杀死渲染线程）→ ProcessROI 42ms→12ms
- doSharpen 改 uint8 域 addWeighted(1+s, -s)（等价 float USM，快 3-5×）
- PipelineConfig.opencv_num_threads=4（小图操作 16 线程同步开销大且与推理抢核）
- pipeline_lipsync_test 增加第 6 参数 out_dir（帧输出指 WSL 原生路径，排除 drvfs 慢写）

## 性能结论（5s 片段，负载下）
- 渲染：全图 Process ~113ms → ProcessROI+优化 14.3ms（7.9×）
- 推理：空闲 23.8ms（8线程）→ 负载 55.7ms（SMT/内存带宽争抢；8物理核机器上 ncnn 8线程 + 渲染4线程 + 消费1线程 已饱和）
