## 三、未修复项与修改建议

### P0 — 并发安全（数据竞争 / UB）

#### 问题 1：AudioPlayer 中 audio_data 和 channels 仍为非原子

**位置**：src/audio/audio_player.cpp:37,42

**问题**：read_frame_pos 和 total_frames 已改为 atomic，但 PortAudio 回调仍读取非原子的 audio_data（line 122/127）和 channels（line 120/121），而 LoadAudio/Init 在主线程修改它们，构成数据竞争（TSAN 可检出）。

**修改建议**（最小改动方案）：

```cpp
// Impl 中：
std::atomic<int>      channels{0};
std::shared_ptr<const std::vector<float>> audio_data;  // 用 shared_ptr 做无锁发布
std::atomic<bool>     data_loaded{false};

// LoadAudio 中：
auto new_data = std::make_shared<std::vector<float>>(...);
std::atomic_store(&impl_->audio_data,
                  std::const_pointer_cast<const std::vector<float>>(new_data));
impl_->data_loaded.store(true, std::memory_order_release);

// 回调中：
auto data = std::atomic_load(&impl->audio_data);
int chans = impl->channels.load(std::memory_order_acquire);
```

**替代方案**：在 LoadAudio/Stop/Init 中先 Pa_StopStream 再修改数据，并在回调入口检查 data_loaded。

#### 问题 4：ThreadSafeQueue 缺移动赋值运算符

**位置**：include/core/thread_safe_queue.h:87-102

**问题**：有移动构造但无移动赋值，违反 Rule of Five；且移动构造漏掉了 peak_size_/total_overflows_/last_push_time_/last_pop_time_/last_heartbeat_ 等统计字段，造成静默数据丢失。

**修改建议**：

```cpp
ThreadSafeQueue& operator=(ThreadSafeQueue&& other) noexcept {
    if (this == &other) return *this;
    Stop();
    std::lock(mutex_, other.mutex_);
    std::lock_guard<std::mutex> lk1(mutex_, std::adopt_lock);
    std::lock_guard<std::mutex> lk2(other.mutex_, std::adopt_lock);
    queue_                = std::move(other.queue_);
    stopped_.store(other.stopped_.load(std::memory_order_relaxed),
                   std::memory_order_relaxed);
    max_capacity_         = other.max_capacity_;
    name_                 = std::move(other.name_);
    heartbeat_timeout_ms_ = other.heartbeat_timeout_ms_;
    peak_size_            = other.peak_size_;             // 补齐
    total_overflows_      = other.total_overflows_;        // 补齐
    last_push_time_       = other.last_push_time_;         // 补齐
    last_pop_time_        = other.last_pop_time_;          // 补齐
    last_heartbeat_       = other.last_heartbeat_;         // 补齐
    total_pushes_.store(other.total_pushes_.load(std::memory_order_relaxed));
    total_pops_.store(other.total_pops_.load(std::memory_order_relaxed));
    other.not_empty_cv_.notify_all();
    other.not_full_cv_.notify_all();
    return *this;
}
```

同时补齐移动构造函数中遗漏的统计字段。

#### 问题 5：ThreadBase::Wait 忽略超时参数

**位置**：include/core/thread_base.h:107-118

**问题**：Wait(timeout_ms) 完全忽略参数，pipeline.cpp:877-883 传入的 shutdown_timeout_ms 是死代码。一旦工作线程卡死，Pipeline::Stop 和析构函数会永久阻塞。

**修改建议**（用 std::async + wait_for 实现超时）：

```cpp
bool Wait(int timeout_ms = -1) {
    if (!thread_.joinable()) {
        FinalizeState();
        return true;
    }
    if (timeout_ms < 0) {
        thread_.join();
    } else {
        auto future = std::async(std::launch::async, [this]{ thread_.join(); });
        if (future.wait_for(std::chrono::milliseconds(timeout_ms))
            != std::future_status::ready) {
            state_.store(State::ERROR, std::memory_order_release);
            std::cerr << "[ThreadBase] Wait 超时 (" << timeout_ms
                      << "ms), 线程被强制 detach" << std::endl;
            thread_.detach();
            FinalizeState();
            return false;
        }
    }
    FinalizeState();
    return true;
}
```

> 注意：detach 会泄漏线程资源，应作为最后手段。更稳健的方案是要求所有 Run() 实现使用可中断的 cv.wait_for。

本项目经过一轮修订后：
- **音视频同步核心 Bug 已解决**（时钟二次方增长、立体声 2×、帧丢失）

2. **Pipeline 架构收敛**：删除 pipeline.cpp 内嵌套 thread 类，复用独立 AudioProcessor/InferenceWorker/RenderThread — 消除双份实现分叉
3. **构建系统与测试基础设施**：CMake 现代化（target-scoped、CONFIGURE_DEPENDS、foreach）、CTest 注册、CI 流水线 — 这是项目工程化的基础

完成 P0 项后，项目可作为生产级 SDK 使用；完成 P1-P3 项后，项目可达到开源级工程质量。
